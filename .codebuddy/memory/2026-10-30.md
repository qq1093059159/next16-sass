# 2026-10-30 工作日志

## 任务：MDX 插件是否支持「目录即内容源」→ 实现了一套完整方案

### 结论（回答用户的问题）

**`@next/mdx` 本身不做目录扫描。** 它是**编译期 loader**，把 `.mdx` 编译成 React 组件，
配合 `pageExtensions` 纳入 Next 的**文件式路由** —— 遵循「一个文件 = 一个路由」。
它**不**做：① 扫描任意目录生成列表页；② 解析 YAML frontmatter；③ 支持 `app/` 之外的目录。

### 本轮实现（模式 B：动态路由 + 目录扫描）

```
content/hello.mdx          ← .mdx（支持 JSX）+ 自定义组件
content/pure-markdown.md   ← 纯 .md
lib/posts.ts               ← 扫描目录 + 动态 import
app/posts/page.tsx         ← 列表页（自动生成）
app/posts/[slug]/page.tsx  ← 详情页 + generateStaticParams
components/mdx/Callout.tsx ← MDX 自定义组件
mdx-components.tsx         ← 组件映射表（接管 h1/h2/a + 登记 Callout）
```

- `next.config.ts`：启用 `createMDX({ extension: /\.(md|mdx)$/ })` + `pageExtensions` 加 md/mdx
- `app/globals.css`：补 `@plugin "@tailwindcss/typography"`（v4 引插件方式，v3 是写进 config）
- 元数据用 **MDX 原生的 `export const metadata`**（ESM 导出），**不用 YAML frontmatter**（默认不支持）

### 三个实测坑（都已写进文档）

1. **动态 import 的 key 必须是「含扩展名的完整文件名」** ——
   写死 `.mdx` 会导致 `.md` 文件找不到（`Cannot find module '@/content/pure-markdown.mdx'`）。
   原因：动态 import 表达式被编译成「目录下所有匹配扩展名文件」的 context map，key 是完整路径。
   → `lib/posts.ts` 因此同时返回 `slug`（给 URL）和 `file`（给 import）。
2. **必须用 `@/` 别名，不能用相对路径** —— 列表页(`app/posts/`)与详情页(`app/posts/[slug]/`)
   到根的相对深度不同，同一表达式指向不同位置。
3. **加文章必须重新 build** —— 目录扫描在构建期（`generateStaticParams` + `fs.readdirSync`）。
   想「加完即见」：`await connection()`（变动态）或 `"use cache"` + `cacheTag` + `revalidateTag`。
