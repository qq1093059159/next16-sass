## next16-clerk 推送到另一个 GitHub 账号（多账号 HTTPS 凭据）

- 现象：`git push` 到 `https://github.com/qq1093059159/next16-sass.git` 报 403 `Permission ... denied to 1256807020`。本机 git 身份是 `qq1256807020 <1256807020@qq.com>`，凭据管理器(manager)里只有一份 `git:https://github.com`（属于 1256807020）。
- 根因：GCM 默认按**域名**缓存凭据，同一域名只能存一个账号，所以第二个账号必被拒。
- 解决：remote URL **带上目标用户名**，GCM 会按 `git:https://qq1093059159@github.com` 单独缓存条目，不影响原账号：

```bash
git remote set-url origin https://qq1093059159@github.com/qq1093059159/next16-sass.git
git branch -M main
git push -u origin main
```

- 结果：推送成功，`main -> main`（6dc5ed9），本地分支跟踪 `origin/main`。
- 注意：仓库已初始化、已有 origin 和历史提交，不要再 `git init` / `git remote add`（会报 already exists，用 `set-url`）；也不要往已有 README.md 追加内容。
- 环境备注：本机没有安装 `gh` CLI；`~/.ssh` 只存在一份 `id_ed25519`。
