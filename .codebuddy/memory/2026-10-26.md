### 最有价值的实测发现

**PPR 模式下页面里 `notFound()` 返回 HTTP 200**（页面是 404 界面，状态码却是 200）。
- 实测：`/notfound`（静态预渲染）-> 200；`/notfound-dynamic`（PPR 壳子 + `await connection()`）-> 仍 200；框架级未匹配路由 -> 404。
- 根因：响应一开始流式输出（预渲染壳子已发首字节），状态码就锁定 200。官方口径一致。
- 结论：加 `await connection()` 救不回来。稳定 404 只有 ①框架级路由未匹配 ②Route Handler 显式返回 404。
- 已在仓库内做成对照实验页 + README 4.27 专章。

过程中一度得出错误结论（以为 `connection()` 能修好），根因是**历次 `pnpm start` 全部 EADDRINUSE，实际测的是旧构建**。教训：本地起服务前必须先杀干净 node 进程，并确认启动日志出现 Ready 且无 EADDRINUSE。

### Markdown 锚点校验的正确做法（重要）
- GitHub 锚点由 **github-slugger** 生成，不是简单的小写+去标点。
  实测差异：`⚠️` 里的 U+FE0F 会进入锚点；连续空格**逐个**转连字符（不合并）；
  CJK 标点（、：（））会被删除；下划线保留。
- 校验方式：`npm pack github-slugger@2` → 用其 `slug()` 复算所有标题，
  并按 GitHub 规则处理重复标题（追加 -1、-2）。
- **结论：标题里不要放 emoji**，否则锚点极脆。本仓库已清掉 §4.27 的 ⚠️。
- 另注意：Python 里的 `re.sub(r' +','-')` 会把连续空格合并成 1 个连字符，
  与 GitHub 行为不一致 —— 不要用自制简化算法校验锚点。
