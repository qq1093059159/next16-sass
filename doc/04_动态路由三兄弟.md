# 第 04 课 · 动态路由三兄弟

> **学习目标**：掌握 `[id]` / `[...id]` / `[[...id]]` 三种动态段，以及 Next 15+ 最容易踩的 `params` Promise 变更。
> **对应代码**：`app/slug/`、`app/slugs/`、`app/(dashboard)/dashboard/users/[id]/`、`app/api/user/[id]/`
> **预计耗时**：40 分钟

---

## 一、核心概念

三个目录并排放，差别一眼可见：

| 写法 | 目录 | 匹配 `/x` | 匹配 `/x/a` | 匹配 `/x/a/b` | `params` 形态 |
|---|---|:-:|:-:|:-:|---|
| 单段 | `app/slug/[id]` | ✅ | ❌ | ❌ | `{ id: '123' }` |
| 捕获段 | `app/slug/[...id]` | ❌ | ✅ | ✅ | `{ id: ['a','b'] }` |
| 可选捕获段 | `app/slugs/[[...id]]` | ✅ | ✅ | ✅ | `{ id: '123' }` 或 `{ id: ['123','456'] }` |

记忆口诀：

- `[id]` —— **一段**，多一段都不行
- `[...id]` —— **一段起步**，可以有多段
- `[[...id]]` —— **零段也行**（这就是和 `[...id]` 的唯一区别）

## 二、真实代码

### 2.1 单段 `app/slug/[id]/page.tsx`

```tsx
//app/shop/[id]/page.tsx
// 基本用法[slug]
export default function Page() {
  return <div>[id]Page</div>;
}
```

### 2.2 捕获段 `app/slug/[...id]/page.tsx`

```tsx
//app/shop/[id]/page.tsx
// 路由片段[...slug]
export default function Page() {
  return <div>[...id]Page</div>;
}
```

### 2.3 可选捕获段 `app/slugs/[[...id]]/page.tsx`

```tsx
//app/shop/[[...id]]/page.tsx
// 可选路由[[...slug]]
"use client";
import { useParams } from "next/navigation";
export default function Page() {
  const params = useParams();
  console.log(params); //{id: '123'}  {id: ['123', '456']} 接受单个值以及多个值
  return <div>[[...slug]]Page</div>;
}
```

> 注意它是 `"use client"` —— 因为用了 `useParams()`（客户端 Hook）。
> 也可以改成服务端组件，直接用 `params` prop，效果一样。

### 2.4 `[[...id]]` 的真实价值：Clerk

`(root)/sign-in/[[...sign-in]]/page.tsx`：

```tsx
import { SignIn } from "@clerk/nextjs";

export default function Page() {
  return <SignIn />;
}
```

可选捕获段让 `/sign-in`、`/sign-in/factor-one`、`/sign-in/sso-callback`
全部落到同一个页面，把多步登录的子路径交给 Clerk 组件自己处理。
这是 Clerk 官方推荐写法。

## 三、`params` 已经是 Promise（Next 15+ 破坏性变更）

这是本课**最重要**的一点。

```tsx
// ✅ Next 15/16 新写法
export default async function Page({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;
}

// ❌ 旧写法（Next 15 之前）：params 是同步对象
export async function PUT(request: Request, context: { params: { id: string } }) {
  const id = +context.params.id;   // ← 没有 await
}
```

### 3.1 服务端组件里

`app/(dashboard)/dashboard/users/[id]/page.tsx`：

```tsx
import React from "react";
// 设置动态meta
export async function generateMetadata({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;
  return {
    title: `User #${id}`,
    description: `User detail page for user ${id}`,
  };
}
export default async function UserDetail({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  return <div>Showing UserDetail for user #{id}</div>;
}
```

### 3.2 Route Handler 里

`app/api/user/[id]/route.ts`：

```tsx
import { NextRequest, NextResponse } from "next/server";
export async function GET(request: NextRequest,
  { params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;
  console.log(id);
  return NextResponse.json({ message: `Hello, ${id}!` });
}
```

`app/api/books/[id]/route.ts`：

```tsx
import books from "@/app/api/db"
export async function PUT(request: Request, context: { params: Promise<{ id: string }> }) {
  const id = +(await context.params).id
  const book = await request.json()
  const index = books.findIndex((b) => b.id === id)
  books[index] = book
  return Response.json(books)
}
export async function DELETE(request: Request, context: { params: Promise<{ id: string }> }) {
  const id = +(await context.params).id
  const index = books.findIndex((b) => b.id === id)
  books.splice(index, 1)
  return Response.json(books)
}
```

> ⚠️ **旧写法是个静默 bug**：不 `await` 的话，`context.params.id` 拿到的是
> `[object Promise]`，`+` 一转就是 `NaN`，不报错但逻辑全错。
> **本仓库所有动态段都已迁移到新写法。**

## 四、动手实验

### 实验 1：验证三种匹配规则

起服务后依次访问：

| URL | 预期 | 命中的目录 |
|---|---|---|
| <http://localhost:3000/slug/foo> | 200，显示 `[id]Page` | `app/slug/[id]` |
| <http://localhost:3000/slug/a/b> | 200，显示 `[...id]Page` | `app/slug/[...id]` |
| <http://localhost:3000/slug/a/b/c> | 200，显示 `[...id]Page` | `app/slug/[...id]` |
| <http://localhost:3000/slugs> | 200，显示 `[[...slug]]Page` | `app/slugs/[[...id]]` |
| <http://localhost:3000/slugs/a/b> | 200，显示 `[[...slug]]Page` | `app/slugs/[[...id]]` |

**关键对照**：

- <http://localhost:3000/slug> → **404**（`[id]` 至少要一段，`[...id]` 也至少要一段）
- <http://localhost:3000/slugs> → **200**（`[[...id]]` 允许零段）

这一条对比就把「可选捕获段」和「捕获段」的差别讲透了。

### 实验 2：打印 params

打开 `app/slugs/[[...id]]/page.tsx`，浏览器控制台已经有 `console.log(params)`。

依次访问：

```text
/slugs/123        → { id: '123' }        ← 单个值是字符串
/slugs/123/456    → { id: ['123','456'] } ← 多个值是数组
/slugs            → { id: undefined }     ← 零段
```

> ⚠️ **类型坑**：因为值可能是字符串也可能是数组，写代码时必须处理两种形态。
> `useParams()` 的返回类型是 `Record<string, string | string[] | undefined>`。

### 实验 3：亲手制造一次「静默 NaN」

在 `app/api/user/[id]/route.ts` 里把 `await params` 去掉试试：

```tsx
export async function GET(request: NextRequest,
  { params }: { params: Promise<{ id: string }> }) {
  const { id } = params;              // ← 故意去掉 await
  console.log(id);
  return NextResponse.json({ message: `Hello, ${id}!` });
}
```

访问 <http://localhost:3000/api/user/886>，你会看到返回 `Hello, [object Promise]!`。

**这就是旧写法的真实危害** —— 不报错，静默地拿到垃圾数据。
（TS 会报错，因为 `params` 的类型是 `Promise<...>`；但如果你手写了 `any` 就绕过了。）

改回来。

### 实验 4：验证 `generateMetadata` 拿到 params

访问 <http://localhost:3000/dashboard/users/1>，然后「查看网页源代码」，
你会看到 `<title>User #1</title>`。

改成访问 `/dashboard/users/42`，title 变成 `User #42`。

## 五、常见错误

| 错误 | 后果 | 正确写法 |
|---|---|---|
| 忘了 `await params` | 静默拿到 `NaN` 或 `[object Promise]` | `const { id } = await params` |
| 类型写成 `{ id: string }` | 运行时才发现可能是数组 | `string \| string[] \| undefined` |
| 用 `[...id]` 却期望匹配 `/x` | 404 | 想匹配零段要用 `[[...id]]` |
| 以为 `[[...id]]` 和 `[...id]` 只差一个星 | 行为完全不同 | 一个允许零段，一个不允许 |
| `generateStaticParams` 忘了 return | 编译报错 | 必须返回数组 |

## 七、小结 & 下一步

- 三兄弟只差「能不能零段」和「能不能多段」。
- `params` 是 Promise，**必须 await** —— 这是 Next 15+ 的破坏性变更。
- 动态路由 + `generateStaticParams` = 静态生成，这是第 11 课的内容。
