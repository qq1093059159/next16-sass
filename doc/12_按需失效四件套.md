# 第 12 课 · 按需失效四件套

> **学习目标**：掌握 Next 16 里主动清缓存的四个 API，以及它们各自的作用域差异。
> **对应代码**：`lib/revalidate-actions.ts`、`app/(root)/revalidate/page.tsx`
> **预计耗时**：30 分钟
> **前置知识**：第 10、11 课

---

## 一、核心概念

内容改了，缓存还没过期 —— 这时需要**主动**失效。Next 16 提供四个 API：

| API | 粒度 | 备注 |
|---|---|---|
| `revalidatePath(path)` | 按 **URL 路径** | 整条路由重新生成 |
| `revalidateTag(tag, profile)` | 按 **标签** | `profile` 决定过期策略，如 `"max"` |
| `updateTag(tag)` | 按标签 | **Next 16 新增**，只能在 Server Action 里，实现「读己所写」 |
| `refresh()` | 客户端 | 刷新客户端 Router Cache 里的动态数据副本 |

> ⚠️ 这几个 API **只能写在服务端**（Server Action / Route Handler），
> 客户端直接 import 会报错。

## 二、真实代码

`lib/revalidate-actions.ts`：

```ts
"use server";

import { revalidatePath, revalidateTag, refresh, updateTag } from "next/cache";

/**
 * 按需失效（On-Demand Revalidation）—— Server Action 版本。
 *
 * Next 16 的四个 API：
 *  - revalidatePath(path)        按【路径】失效：该路径下的页面重新生成
 *  - revalidateTag(tag, profile) 按【标签】失效：profile 决定过期策略
 *  - updateTag(tag)             立即失效，且实现「读己所写」语义（只能在 Server Action 里）
 *  - refresh()                  刷新客户端缓存（客户端侧的动态数据也会一起刷新）
 *
 * 注意：这几个 API 只能写在服务端，客户端直接 import 会报错。
 */

/** 按路径失效：重置 /ssg/1 这条路由的缓存 */
export async function invalidateByPath() {
  revalidatePath("/ssg/1");
}

/** 按标签失效：profile 传预设名（seconds/minutes/hours/days/weeks/max） */
export async function invalidateByTag() {
  revalidateTag("post-1", "max");
}

/** Next 16 新 API：立即让标签失效，并让本次写入对当前请求立即可见 */
export async function invalidateByUpdateTag() {
  updateTag("post-1");
}

/** 刷新客户端缓存 */
export async function refreshClientCache() {
  refresh();
}
```

## 三、⚠️ 一个容易踩的参数坑

```ts
revalidateTag("post-1");          // ❌ 编译报错
```

**Next 16.3.8 的 `revalidateTag` 是两个参数**：

> 下面是**逐字摘自** `node_modules/next/dist/server/web/spec-extension/revalidate.d.ts` 的类型声明：

```ts
export declare function revalidateTag(
  tag: string,
  profile: string | CacheLifeConfig
): undefined;
```

写成一个参数会报：

```text
error TS2554: Expected 2 arguments, but got 1.
```

第二个参数是 `cacheLife` 的预设名（`seconds`/`minutes`/`hours`/`days`/`weeks`/`max`），
或者一个 `{ expire: number }` 对象。

## 四、动手实验

### 实验 1：按路径失效

```bash
pnpm build && pnpm start
curl -I http://127.0.0.1:3000/ssg/1 | grep -i x-nextjs-cache    # HIT
```

浏览器打开 <http://localhost:3000/revalidate>，点「按路径失效」按钮，
再执行一次上面的 curl。

**预期**：缓存被清掉，`x-nextjs-cache` 从 `HIT` 变成 `MISS`（重新生成）。

### 实验 2：按标签失效

先访问 <http://localhost:3000/ssg/1>（生成缓存，它带 `cacheTag("post-1")`），
然后在 `/revalidate` 页点「按标签失效」。

**预期**：同样清掉了 `/ssg/1` 的缓存 —— 因为那个缓存打了 `post-1` 标签。

**关键区别**：`revalidatePath("/ssg/1")` 会让**该路径下所有页面**失效；
`revalidateTag("post-1")` 只让**打了这个标签的条目**失效。列表页里改了第 1 条，
用 tag 更精准。

### 实验 3：观察 updateTag 的自动刷新

在 `/revalidate` 页点「updateTag(post-1)」。

**预期**：页面在 Action 执行后**自动刷新**（不需要你手写 `router.refresh()`）。
这就是「读己所写」—— 你刚写的数据，立刻就能被读到。

### 实验 4：亲手制造编译错误

把 `lib/revalidate-actions.ts` 里的 `revalidateTag("post-1", "max")` 改成
`revalidateTag("post-1")`，然后 `pnpm build`。

**预期**：`error TS2554: Expected 2 arguments, but got 1.`

改回来。

## 五、常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| `revalidateTag` 只写一个参数 | TS 编译错误 | 加 `profile` 参数 |
| 在客户端组件里 import 这些 API | 运行时报错 | 只能服务端用 |
| 忘了先 `cacheTag()` | 按标签失效没效果 | 缓存处必须打标签 |
| 用 `revalidatePath` 做精细失效 | 连带清掉同路径其它页面 | 用 `revalidateTag` |
| 在 Server Action 里用 `updateTag` 之外的地方 | 报错 | `updateTag` 只能在 Server Action |

## 七、小结 & 下一步

- 路径级用 `revalidatePath`，条目级用 `revalidateTag`/`updateTag`。
- `revalidateTag(tag, profile)` —— **两个参数**。
- `updateTag` 是 Next 16 新增，能实现「读己所写」。
