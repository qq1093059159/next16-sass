# 第 02 课 · 路由约定文件八件套

> **学习目标**：搞清楚 Next.js 是怎么靠「文件名」而不是「配置」来驱动渲染的。
> **对应代码**：`app/layout.tsx`、`app/basic/`、`app/default.tsx`、`app/@team/default.tsx`
> **预计耗时**：40 分钟
> **前置知识**：第 01 课

---

## 一、核心概念

App Router 没有 `routes.js` 之类的路由表。**文件名就是路由契约** —— 你把文件放对位置，
框架就自动认。Next.js 一共认这八个约定文件：

| 文件 | 作用 | 本仓库位置 | 硬性规则 |
|---|---|---|---|
| `layout.tsx` | 布局外壳，**不随导航重挂载** | `app/layout.tsx`、`app/(root)/layout.tsx`、`app/basic/layout.tsx` | 根 layout **必须**含 `<html><body>` |
| `template.tsx` | 布局外壳，**每次导航重新挂载** | `app/basic/template.tsx` | 与 layout 只差这一点 |
| `page.tsx` | 路由页面本体 | 到处都是 | 一个目录只能有一个；只有 `page` 才对外可见 |
| `loading.tsx` | Suspense 边界 | `app/loading.tsx`、`app/basic/loading.tsx` | 自动包 `<Suspense fallback>` |
| `error.tsx` | 段级错误边界 | `app/(root)/error.tsx`、`app/basic/error.tsx` | **必须是 `"use client"`**，且要接 `error` / `reset` |
| `global-error.tsx` | 全局错误边界 | `app/global-error.tsx` | 会**替换根 layout**，须自己输出 `<html><body>` |
| `not-found.tsx` | 404 | `app/not-found.tsx` | 由 `notFound()` 或未匹配路由触发 |
| `default.tsx` | 平行路由 slot 兜底 | `app/default.tsx`、`app/@team/default.tsx`、`app/@analytics/default.tsx` | 平行路由专属 |

---

## 二、嵌套渲染顺序

以 `/basic/a` 为例，框架自上而下包裹：

```text
app/layout.tsx                    ← 根布局
  └─ app/loading.tsx              ← 外层 Suspense 边界
       └─ app/basic/layout.tsx    ← basic 段布局
            └─ app/basic/template.tsx
                 └─ app/basic/loading.tsx   ← 内层 Suspense
                      └─ app/basic/error.tsx ← 错误边界
                           └─ app/basic/a/page.tsx
```

**记忆要点**：`layout` 包一切，`template` 只包 `page`，`loading` 是 Suspense，
`error` 兜住同级及以下。

## 三、逐个看真实代码

### 3.1 `layout.tsx` —— 根布局

`app/layout.tsx`（注意它同时消费了两个平行路由 slot）：

```tsx
import type { Metadata } from "next";
import "./globals.css";
import { ThemeProvider } from "next-themes";
import { Analytics } from "@vercel/analytics/next";
import { SpeedInsights } from "@vercel/speed-insights/next";

export const metadata: Metadata = {
  title: "App",
  description: "Generated by create next app",
};

export default function DashboardLayout({
  children,
  team,
  analytics,
}: {
  children: React.ReactNode;
  team: React.ReactNode;
  analytics: React.ReactNode;
}) {
  return (
    <html lang="en" data-theme="dark" suppressHydrationWarning>
      <body>
        <ThemeProvider
          attribute="class"
          defaultTheme="system"
          enableSystem
          disableTransitionOnChange
        >
          <main className="bg-white text-black dark:bg-black dark:text-white">
            {/* 加载平行路由 */}
            {team}
            {children}
            {analytics}
            <SpeedInsights />
            <Analytics />
          </main>
        </ThemeProvider>
      </body>
    </html>
  );
}
```

三个要点：

1. **根 layout 必须自带 `<html><body>`** —— 它是整个文档的壳。
2. `children` 是「下一层」渲染结果。
3. `team` 和 `analytics` 是**平行路由 slot**（第 03 课细讲）—— prop 名必须和 `@team` / `@analytics` 目录名一模一样。

### 3.2 `loading.tsx` —— Suspense 语法糖

`app/basic/loading.tsx` 全文：

```tsx
export default function Loading() {
  return (
    <div>
      <h1>Loading...</h1>
    </div>
  );
}
```

它**不需要**你手写 `<Suspense>`。框架会自动把这个段包成：

> 下面是**伪码**，用于说明 `loading.tsx` 被框架展开后的等价结构（仓库里没有这段代码）：

```tsx
<Suspense fallback={<Loading />}>
  {children}
</Suspense>
```

### 3.3 `error.tsx` —— 段级错误边界

`app/basic/error.tsx`（注意 `error` / `reset` 两个 prop **必须接**）：

```tsx
"use client";

import { useEffect } from "react";

/**
 * basic 段的错误边界。
 *
 * 演示：把 app/basic/a/page.tsx 里那行 `throw new Error("错误")` 的注释打开，
 * 访问 /basic/a 就会命中这里（而不是 (root)/error.tsx）——
 * 错误边界按「最近的祖先段」生效。
 */
export default function Error({
  error,
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  useEffect(() => {
    console.error("[basic error boundary]", error);
  }, [error]);

  return (
    <div>
      <h1 className="text-red-600">Error（basic 段）</h1>
      <p className="mt-2 text-sm opacity-70">{error.message}</p>
      <button
        onClick={() => reset()}
        className="mt-3 rounded-md border border-gray-300 px-3 py-1 text-sm dark:border-gray-700"
      >
        重试
      </button>
    </div>
  );
}
```

> ⚠️ **实测过的坑**：很多教程里的 `error.tsx` 只写一句 `return <div>error</div>`。
> 那样等于没做错误边界 —— 拿不到错误信息，用户也没法重试。**必须接 `error` 和 `reset`**。

### 3.4 `global-error.tsx` —— 最后的兜底

`app/global-error.tsx`：

```tsx
"use client";

/**
 * 全局错误边界 —— 根 layout 都救不回来时才生效。
 *
 * ⚠️ 关键区别：global-error.tsx 会【替换掉根 layout】，
 *    所以它必须自己输出 <html> 和 <body>，
 *    否则浏览器会拿到一个没有 html/body 的文档，页面全白。
 *
 * ⚠️ 它也必须是 "use client"。
 */
export default function GlobalError({
  error,
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  return (
    <html lang="zh-CN">
      <body
        style={{
          fontFamily: "system-ui, sans-serif",
          padding: "3rem",
          color: "#111",
          background: "#fff",
        }}
      >
        <h1 style={{ fontSize: "1.5rem", color: "#dc2626" }}>全局错误（global-error）</h1>
        <p style={{ marginTop: "0.75rem" }}>
          根 layout 已经渲染失败，这里是最后一道兜底 —— 注意本页自带{" "}
          <code>&lt;html&gt;</code> / <code>&lt;body&gt;</code>。
        </p>
        <pre
          style={{
            marginTop: "1rem",
            padding: "0.75rem",
            background: "#f5f5f5",
            borderRadius: "0.5rem",
            fontSize: "0.75rem",
            whiteSpace: "pre-wrap",
          }}
        >
          {error.message}
          {error.digest ? `\ndigest: ${error.digest}` : ""}
        </pre>
        <button
          onClick={() => reset()}
          style={{
            marginTop: "1rem",
            padding: "0.5rem 1rem",
            borderRadius: "0.375rem",
            background: "#111",
            color: "#fff",
            border: "none",
            cursor: "pointer",
          }}
        >
          重试
        </button>
      </body>
    </html>
  );
}
```

> ⚠️ **它会替换掉根 layout**，所以必须自己输出 `<html>` 和 `<body>`，
> 否则浏览器拿到一个没有 html/body 的文档，**页面全白**。

### 3.5 `not-found.tsx` —— 404

`app/not-found.tsx`：

```tsx
import Link from "next/link";

/**
 * 404 页面。
 *
 * 触发方式：
 *  1. 路由没匹配上（比如 /nonexistent）
 *  2. 组件里调用了 notFound()（本项目在 /notfound 和 /ssg/[id] 演示）
 *
 * 层级：越靠近的 not-found.tsx 优先级越高。
 */
export default function NotFound() {
  return (
    <div className="mx-auto flex min-h-[60vh] max-w-2xl flex-col items-center justify-center p-6 text-center">
      <p className="text-6xl font-black opacity-20">404</p>
      <h1 className="mt-2 text-2xl font-bold">页面不存在</h1>
      <p className="mt-2 text-sm opacity-70">
        你访问的地址没有对应的路由，或者内容被 notFound() 主动判定为不存在。
      </p>
      <Link
        href="/knowledge"
        className="mt-6 rounded-md bg-gray-900 px-4 py-2 text-sm text-white dark:bg-white dark:text-black"
      >
        回到知识点地图
      </Link>
    </div>
  );
}
```

### 3.6 `default.tsx` —— 平行路由兜底

`app/@team/default.tsx`：

```tsx
// 兜底页面default.tsx
export default function Default() {
  return (
    <div>team default</div>
  )
}
```

`app/default.tsx`：

```tsx
// 兜底页面
export default function Default() {
  return (
    <div>root default</div>
  )
}
```

`default.tsx` 的行为细节留到第 03 课（平行路由）讲。

## 四、动手实验

### 实验 1：让 error.tsx 真的触发

打开 `app/basic/a/page.tsx`，把：

```tsx
  //遇到异常会自动跳转到error组件
  // throw new Error("错误");
```

改成：

```tsx
  throw new Error("这是我故意抛出的错误");
```

访问 <http://localhost:3000/basic/a>，你会看到 `basic/error.tsx` 的界面，
页面上显示错误信息，有个「重试」按钮。

**观察**：

1. 错误信息是从 `error.message` 拿到的 —— 这就是为什么必须接 `error` prop。
2. 点「重试」会重新渲染这一段（但因为 throw 还在，会再次报错）。

**做完记得把 `throw` 注释掉。**

### 实验 2：改 loading 界面

改 `app/basic/loading.tsx` 里的文案，随便改个字。

访问 <http://localhost:3000/basic/a> —— 页面要等 5 秒（`app/basic/a/page.tsx` 里
有个真实的 5 秒 `setTimeout`），这 5 秒里显示的就是你改过的 loading 界面。

对比 <http://localhost:3000/basic/b> —— 立即返回，**不会**看到 loading。

> 这就是 `loading.tsx` 的作用：**它把这个段里所有可能挂起的部分包成一个 Suspense 边界**。

### 实验 3：验证 error.tsx 的层级关系

刚才 `basic/a` 的错误命中了 `app/basic/error.tsx`。
如果你把 `throw` 挪到 `app/(root)/about/page.tsx`（那里有一行注释掉的 `throw`），
它会命中 `app/(root)/error.tsx` 而不是 basic 的那个。

**就近原则**：错误边界只捕获**同级及以下**的错误。

## 五、常见错误

| 错误 | 后果 | 正确写法 |
|---|---|---|
| `error.tsx` 忘了 `"use client"` | 编译报错 | 错误边界必须能处理事件，是客户端组件 |
| `error.tsx` 不接 `error`/`reset` | 拿不到错误、无法重试 | 把两个 prop 都解构出来 |
| `global-error.tsx` 忘了 `<html><body>` | 触发时整页白屏 | 自己补上 |
| 一个目录放两个 `page.tsx` | 构建报错 | 一个目录只能有一个 |
| `loading.tsx` 里写 `"use client"` | 能跑但没必要 | loading 一般是服务端组件 |
| 把 `page.tsx` 删了 | 该 URL 直接 404 | 只有 `page.tsx` 才对外可见 |

## 七、小结 & 下一步

- 八个文件名 = 八种约定，各有硬性规则，违反了在**构建期**就会报错。
- `error.tsx` 必须接 `error` / `reset`；`global-error.tsx` 必须自带 `<html><body>`。
- `default.tsx` 是第八件，但它属于平行路由体系。
