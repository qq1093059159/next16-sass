# 第 03 课 · 路由组与平行路由

> **学习目标**：分清 App Router 里最容易混的两个概念 —— 圆括号和 @ 前缀。
> **对应代码**：`app/(auth)/`、`app/(dashboard)/`、`app/(root)/`、`app/@team/`、`app/@analytics/`
> **预计耗时**：45 分钟
> **前置知识**：第 02 课

---

## 一、核心概念

两个都「不进 URL」，但**完全不是一回事**：

| | 路由组 `(folder)` | 平行路由 `@folder` |
|---|---|---|
| **符号** | 圆括号 | `@` 前缀 |
| **是否进 URL** | ❌ 不进 | ❌ 不进 |
| **作用** | 给路由**分组**，可挂独立 layout | 把一个额外 UI **作为 prop 注入**同级 layout |
| **消费方式** | 无需特殊接收，正常渲染 children | layout 必须**声明同名 prop** |
| **本仓库** | `(auth)` `(dashboard)` `(root)` | `@team` `@analytics` |

**一句话记忆**：

- 路由组 = **整理代码结构**（我只是想把这几个页面放一起）
- 平行路由 = **同时渲染两个东西**（比如主内容 + 一个侧边栏）

## 二、路由组 `(folder)`

### 2.1 真实目录

```text
app/
├─ (auth)/
│  ├─ mylogin/            · 传统 fetch('/api/login') + router.push
│  ├─ serverlogin/        · Server Action + FormData + .bind()
│  └─ serverzodlogin/     · useActionState + Zod 校验 ★最推荐
├─ (dashboard)/
│  └─ dashboard/
│     ├─ layout.tsx      · 嵌套布局
│     ├─ analytics/      · 普通路由（≠ @analytics slot！）
│     └─ users/[id]/     · 动态路由 + generateMetadata
└─ (root)/
   ├─ layout.tsx          · 挂载 Navbar
   ├─ page.tsx            · 首页（接管根路径 /）
   ├─ error.tsx           · 段级错误边界
   ├─ home/               · useEffect 客户端守卫（反模式）
   ├─ about/ albums/ books/ sign-in/[[...sign-in]]/
   └─ ...（本仓库大部分演示页都在这）
```

### 2.2 URL 怎么算

`(auth)` 里的 `mylogin` 页，URL 是 `/mylogin` —— **不是** `/auth/mylogin`。

同理 `(root)/page.tsx` 接管的是根路径 `/`；
`(dashboard)/dashboard/users` 的 URL 是 `/dashboard/users`。

### 2.3 路由组用来挂独立 layout

`app/(dashboard)/dashboard/layout.tsx`：

```tsx
import React from "react";

export default function DashboardLayout({
  children,
}: Readonly<{
  children: React.ReactNode;
}>) {
  return (
    <div>
      <h2>Dashboard layout</h2>
      {children}
    </div>
  );
}
```

只要访问 `/dashboard/**` 下的任何页面，这个 layout 都会包住它们。
**路由组是实现「同一 URL 前缀下、共享局部布局」的标准手段。**

### 2.4 命名陷阱

`app/(dashboard)/dashboard/analytics/`（普通路由，URL = `/dashboard/analytics`）
和 `app/@analytics/`（平行路由 slot）**同名但毫无关系**。

前者是一个真实页面，后者是注入到根 layout 的 UI 片段。看代码时务必分辨。

## 三、平行路由 `@folder`

### 3.1 真实代码

`app/@team/page.tsx`：

```tsx
import React from 'react'

export default function Team() {
  return (
    <div>Team page</div>
  )
}
```

`app/@team/default.tsx`：

```tsx
// 兜底页面default.tsx
export default function Default() {
  return (
    <div>team default</div>
  )
}
```

`app/@analytics/page.tsx`：

```tsx
import React from "react";

export default function Analytics() {
  return <div>Analytics page</div>;
}
```

`app/@analytics/default.tsx`：

```tsx
// 兜底页面default.tsx
export default function Default() {
  return <div>analytics default</div>;
}
```

### 3.2 消费方式：layout 声明同名 prop

关键在于 `app/layout.tsx` 的 props 名字必须和 `@` 目录名**一模一样**：

```tsx
export default function DashboardLayout({
  children,
  team,
  analytics,
}: {
  children: React.ReactNode;
  team: React.ReactNode;
  analytics: React.ReactNode;
}) {
  return (
    <html lang="en" data-theme="dark" suppressHydrationWarning>
      <body>
        <ThemeProvider
          attribute="class"
          defaultTheme="system"
          enableSystem
          disableTransitionOnChange
        >
          <main className="bg-white text-black dark:bg-black dark:text-white">
            {/* 加载平行路由 */}
            {team}
            {children}
            {analytics}
            <SpeedInsights />
            <Analytics />
          </main>
        </ThemeProvider>
      </body>
    </html>
  );
}
```

三个 prop 的对应关系：

| 目录 | layout 里的 prop | 渲染位置 |
|---|---|---|
| `app/@team/` | `team` | `{team}` |
| `app/@analytics/` | `analytics` | `{analytics}` |
| `app/`（普通子路由） | `children` | `{children}` |

### 3.3 `default.tsx` 的真实行为（已实测）

这是最容易搞错的地方。**实测结论**：

| 场景 | slot 渲染什么 |
|---|---|
| 硬刷新 / 直接输入 URL，**当前路由下没有对应的 slot 内容** | 渲染该 slot 的 **`default.tsx`** |
| 硬刷新到**有**对应 slot page 的路由（如 `/`） | 渲染该 slot 的 **`page.tsx`** |
| 软导航（`<Link>` 点击） | Next **保留上一次 slot 的状态**（同一 slot 在不同路由间切换时不重置） |

实测命令（先 `pnpm build && pnpm start`）：

```bash
curl -s http://127.0.0.1:3000/dashboard/users/1 | grep -o "team default"
# → team default        （该路由下没有 team slot，走了 default.tsx）

curl -s http://127.0.0.1:3000/ | grep -o "Team page"
# → Team page           （/ 下有 team slot 的 page.tsx）
```

> ⚠️ **常见误解**：很多资料说「硬刷新会走 not-found」。**实测不是这样**，
> Next 16 渲染的是 `default.tsx`。`default.tsx` 缺了，slot 才会空掉（严重时 404）。

### 3.4 为什么 `default.tsx` 必须成对

`page.tsx` 和 `default.tsx` **必须成对存在**。三个文件共同构成完整兜底链：

```text
app/default.tsx            ← 根级兜底
app/@team/default.tsx      ← @team slot 兜底
app/@analytics/default.tsx ← @analytics slot 兜底
```

## 四、动手实验

### 实验 1：观察 slot 内容随路由变化

```bash
curl -s http://127.0.0.1:3000/ | grep -o "Team page\|team default"
curl -s http://127.0.0.1:3000/dashboard/users/1 | grep -o "Team page\|team default"
curl -s http://127.0.0.1:3000/about | grep -o "Team page\|team default"
```

**预期**：

- `/` → `Team page`（该路由下有 team slot 的 page）
- `/dashboard/users/1` → `team default`（没有，走 default）
- `/about` → 同样走 default（`/about` 属于 `(root)` 组，没有 team slot）

### 实验 2：删掉 `default.tsx` 体会兜底消失

```bash
mv app/@team/default.tsx app/@team/default.tsx.bak
pnpm build && pnpm start
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3000/dashboard/users/1
```

**预期**：状态码不再是 200（slot 无内容可渲染时 Next 会报 404 或渲染空）。
恢复：

```bash
mv app/@team/default.tsx.bak app/@team/default.tsx
```

> 这是平行路由**最高频的线上事故**：本地开发时在 `/` 路由下调试正常，
> 一上线用户点某个深层链接就 404 —— 因为那个路由下没有 slot 内容，
> 而 `default.tsx` 恰好漏了。

### 实验 3：观察软导航的状态保持

浏览器里打开 `/`，点 Navbar 里的链接到 `/about`，再点回 `/`。

**观察**：slot 区域的内容在软导航过程中**不闪**（Next 保留了 slot 状态），
而硬刷新时它会重新走 `default.tsx`。

## 五、常见错误

| 错误 | 后果 | 正确写法 |
|---|---|---|
| layout 里 prop 名和 `@目录名` 不一致 | TS 报错 / slot 永远不渲染 | 严格同名：`@team` → `team` |
| slot 只有 `page.tsx` 没有 `default.tsx` | 硬导航到无 slot 的路由时 404 | 两个成对写 |
| 误以为 `@analytics` 和 `(dashboard)/dashboard/analytics` 是同一个东西 | 排查半天找不到代码 | 一个是 slot，一个是真实页面 |
| 把路由组当成「URL 前缀」 | URL 设计全乱 | 路由组**完全不进 URL** |

## 七、小结 & 下一步

- 路由组整理代码结构，平行路由同时渲染两个 UI。
- 平行路由靠 layout 里**同名 prop**消费；`page.tsx` 与 `default.tsx` 必须成对。
- `default.tsx` 在硬导航到「无 slot 的路由」时被渲染（**不是** not-found）。
