# 第 27 课 · 零依赖主题切换（弃用 next-themes）

> **学习目标**：搞清「亮/暗模式」到底需要多少代码，并亲手实现一套**零第三方依赖**的主题切换 —— 同时彻底消灭 `A tree hydrated but some attributes of the server rendered HTML didn't match` 这类报错。
> **对应代码**：`lib/theme.ts`、`components/theme/ThemeScript.tsx`、`components/theme/ThemeToggle.tsx`、`components/DarkMode.tsx`、`app/layout.tsx`、`app/globals.css`
> **预计耗时**：40 分钟
> **前置知识**：第 20 课（SEO 约定文件）、第 04 课（客户端组件边界）
> **说明**：本课是**扩展课**，选学。想给项目换主题体系 / 排查 hydration 报错时读。

---

## 一、先看报错长什么样

你在项目里接了 `next-themes`，dev 一开就报这个：

```text
A tree hydrated but some attributes of the server rendered HTML didn't match
the client properties. This won't be patched up.

  <html
    lang="zh-CN"
-   className="light"
-   style={{color-scheme:"light"}}
  >
```

**注意 `-` 标记的那两行** —— 服务端渲染出来是 `class="light"`，客户端是别的值。

### 1.1 为什么会不一致

| 环节 | 服务端 | 客户端 |
|---|---|---|
| 用户上次选的主题 | **不知道**（localStorage 只有浏览器能读） | 知道 |
| 系统偏好 | **不知道** | 知道（`prefers-color-scheme`） |
| 渲染出的 `<html>` | `class="light"`（假定值） | `class="dark"`（真实值） |

React 在 hydration 时逐个比对服务端 HTML 与客户端虚拟 DOM 的属性 → 发现 `class` 不一样 → 报警告。

> **关键认知**：这个错**不是 bug**，是「服务端不知道客户端状态」的必然结果。
> 解决办法只有三条：① 让服务端也知道（读 Cookie → 失去静态能力）；
> ② 让两边渲染出一样的（`suppressHydrationWarning`）；
> ③ 让差异发生在 hydration **之后**（脚本在 `<head>` 里先把 class 打好）。

本课用的是 ② + ③ 的组合。

## 二、为什么弃用 `next-themes`

`next-themes` 只做两件事：

1. 把 `class="dark"` 打到 `<html>` 上
2. 提供一个 React Context，让组件能读/写主题

这两件事用 **20 行原生 DOM** 就能做完。而引入它的代价：

| 代价 | 说明 |
|---|---|
| 根布局必须包 `<ThemeProvider>` | 给整棵子树加了一层约束 |
| 主题状态在 Context 里 | 想读主题的组件必须是 Client Component 且在 Provider 内 |
| 一个第三方依赖 | 内容引擎基座要能独立迁移，依赖越少越好 |

shadcn/ui 官方文档给了两种做法：**`next-themes`（默认）** 与 **手动 class 切换**。
本项目选后者 —— 因为 Tailwind v4 的 `dark:` 变体本来就是由 `.dark` 类驱动的，缺的只是「谁来打这个类」。

## 三、三层机制

```text
① CSS 层：两套变量 + .dark 类选哪套
   :root { --bg: #ffffff; ... }      ← 亮色
   .dark { --bg: #0f1117; ... }      ← 暗色
   @custom-variant dark (&:is(.dark *));

② JS 层：把 .dark 类打到 <html> 上
   applyTheme() → classList.toggle("dark") + style.colorScheme

③ 时机层：内联脚本在 hydration 之前执行（防闪烁）
   <head> 里的 <script> 同步跑 → 首屏就是对的颜色
```

三层缺一不可：
- 只有 ① → 永远亮色（用户点了没反应）
- ① + ② → 能切，但首屏会闪一下亮色再变暗
- ① + ② + ③ → 完整

## 四、核心代码逐段讲解

### 4.1 类型与常量（`lib/theme.ts`）

```ts
export type Theme = "light" | "dark" | "system";
export type ResolvedTheme = "light" | "dark";

export const THEME_STORAGE_KEY = "theme";
export const THEME_EVENT = "theme:change";
```

`Theme` 是**用户偏好**（可以是 `system`），`ResolvedTheme` 是**实际生效**的值（`system` 解析后的结果）。
这两个概念必须分开 —— 否则「跟随系统」这个态无处安放。

### 4.2 applyTheme：全部机制的核心

```ts
export function applyTheme(theme: Theme): ResolvedTheme {
  const dark = theme === "dark" || (theme === "system" && systemPrefersDark());
  const root = document.documentElement;

  root.classList.toggle("dark", dark);
  // color-scheme 让浏览器原生 UI（滚动条、表单控件、选中区）也跟着变
  root.style.colorScheme = dark ? "dark" : "light";
  // 解析后的实际主题 —— CSS 用它决定显示哪个图标
  root.setAttribute("data-theme", dark ? "dark" : "light");
  // 用户原始偏好 —— CSS 用它决定「跟随系统」这一项是否打勾
  root.setAttribute("data-theme-pref", theme);

  return dark ? "dark" : "light";
}
```

四个动作各有用途：

| 动作 | 作用 |
|---|---|
| `classList.toggle("dark", dark)` | 触发 Tailwind 的 `dark:` 变体 + `.dark` 里的 CSS 变量 |
| `style.colorScheme` | 浏览器原生 UI 跟随（滚动条、表单边框、文本选中色） |
| `data-theme` | 解析后的实际主题，供 CSS 精确匹配 |
| `data-theme-pref` | 原始偏好，供 CSS 区分「显式选了暗色」与「跟随系统恰好是暗色」 |

### 4.3 读 / 写 / 切换

```ts
/** 读取用户偏好（localStorage 里的原始值，未解析 system） */
export function getStoredTheme(): Theme {
  try {
    const v = localStorage.getItem(THEME_STORAGE_KEY);
    return v === "light" || v === "dark" || v === "system" ? v : "system";
  } catch {
    // 隐私模式下 localStorage 可能抛异常
    return "system";
  }
}

/** 读取当前已生效的主题（读 DOM，不读 localStorage） */
export function getResolvedTheme(): ResolvedTheme {
  if (typeof document === "undefined") return "light";
  return document.documentElement.classList.contains("dark") ? "dark" : "light";
}

/** 设置并持久化主题（会派发 THEME_EVENT） */
export function setTheme(theme: Theme): ResolvedTheme {
  try {
    localStorage.setItem(THEME_STORAGE_KEY, theme);
  } catch {
    // 存不了就只在本次会话生效
  }
  const resolved = applyTheme(theme);
  window.dispatchEvent(new Event(THEME_EVENT));
  return resolved;
}

/** 在 light / dark 之间切换（用户主动点击按钮时用） */
export function toggleTheme(): ResolvedTheme {
  return setTheme(getResolvedTheme() === "dark" ? "light" : "dark");
}
```

> ⚠️ `try/catch` 不是防御性编程洁癖 —— **Safari 隐私模式下 `localStorage.setItem` 会直接抛
> `QuotaExceededError`**，不 catch 的话点击切换会静默失败。

## 五、⚠️ 两个必须绕开的 hydration 坑

### 5.1 坑 1：图标不能用 React state 控制

服务端渲染时读不到 `localStorage`，所以「当前是不是暗色」这个状态**客户端首帧才知道**。

```tsx
// ❌ 这样写必然 hydration mismatch
const [isDark, setIsDark] = useState(false);
useEffect(() => setIsDark(document.documentElement.classList.contains("dark")), []);
return isDark ? <Moon /> : <Sun />;
```

服务端渲染出 `<Sun>`，客户端首帧变成 `<Moon>` → 不一致。

> `useSyncExternalStore` 也救不了：它的 `getSnapshot` 在客户端**首次 hydration** 时就会调用，
> 返回真实值（`dark`），而服务端 HTML 里是 `light` → 照样 mismatch。

**本课解法：两个图标都在 DOM 里，靠 CSS 切换显隐**（shadcn/ui 官方 v4 模板同款）：

```tsx
export default function ThemeToggle({ className = "" }: { className?: string }) {
  return (
    <button
      type="button"
      onClick={() => toggleTheme()}
      title="切换亮色 / 暗色模式"
      className={
        "relative inline-flex h-8 w-8 items-center justify-center rounded-md border " +
        "border-gray-300 transition hover:bg-gray-100 " +
        "dark:border-gray-700 dark:hover:bg-gray-800 " +
        className
      }
    >
      <Sun className="h-4 w-4 rotate-0 scale-100 transition-all dark:-rotate-90 dark:scale-0" />
      <Moon className="absolute h-4 w-4 rotate-90 scale-0 transition-all dark:rotate-0 dark:scale-100" />
      <span className="sr-only">切换亮色 / 暗色模式</span>
    </button>
  );
}
```

服务端和客户端渲染出的 HTML **完全一致** → 天然零 hydration 风险。

「当前是不是暗色」这个状态只存在于 `<html>` 的 class 上，**由 CSS 决定谁可见，JS 完全不参与渲染判断**。

### 5.2 坑 1 的变体：三态菜单也不能用 radio

三态菜单（浅色 / 深色 / 跟随系统）如果用 `DropdownMenuRadioGroup`，就必须知道「当前选中哪一项」
→ 必须用 React state 持有 → 又回到坑 1。

**解法：当前项的标记交给 CSS。**

```tsx
<DropdownMenuItem onClick={() => setTheme("light")} data-theme-value="light">
  <Check className="theme-current-mark mr-2 h-4 w-4" />
  浅色
</DropdownMenuItem>
```

```css
.theme-current-mark { opacity: 0; }

:root[data-theme="light"] [data-theme-value="light"],
:root[data-theme="dark"]  [data-theme-value="dark"] { opacity: 1; }
:root[data-theme-pref="system"] [data-theme-value="system"] { opacity: 1; }
```

于是 React 完全不持有主题状态 → 零 hydration 风险。

> 💡 顺带一提：`<Button>` 来自 shadcn，它**没有 `position: relative`** ——
> 绝对定位的月亮图标会跑到最近的定位祖先（可能是 `<body>`）去。
> 用 `<Button className="relative">` 补上。

### 5.3 坑 2：`<html>` 必须加 `suppressHydrationWarning`

`class` 与 `style` 是**客户端脚本**加的，而服务端渲染时不知道用户偏好 → 属性不一致 → React 报错。

```tsx
<html lang="en" suppressHydrationWarning>
```

这个属性**只压制 `<html>` 自身属性**的警告，不影响任何子节点 —— 所以它不会掩盖真正的 hydration 问题。

## 六、防闪烁：为什么脚本必须内联在 `<head>`

```tsx
// components/theme/ThemeScript.tsx
import { themeInitScript } from "@/lib/theme";

export default function ThemeScript() {
  return <script dangerouslySetInnerHTML={{ __html: themeInitScript }} />;
}
```

```tsx
// app/layout.tsx
<html lang="en" suppressHydrationWarning>
  <head>
    <ThemeScript />
  </head>
  <body>
    {/* … */}
  </body>
</html>
```

### 6.1 三种方案的对比

| 方案 | 首屏 | 代价 |
|---|---|---|
| 服务端读 Cookie 渲染对应 class | 完美无闪 | **整站失去静态能力**（每个请求都要读偏好） |
| `next/script` 的 `<Script>` | **会闪** | 脚本异步加载，等下完执行时页面已经闪了一帧亮色 |
| **内联 `<script>` 在 `<head>`** | 完美无闪 | 无 |

内联脚本在 **HTML 解析阶段**同步执行，时机最早 → 首屏就是用户上次选的配色。

### 6.2 脚本内容

```js
(function () {
  try {
    var K = "theme";
    function sys() { return window.matchMedia("(prefers-color-scheme: dark)").matches }
    function apply(pref) {
      var d = (pref === "dark") || (pref === "system" && sys());
      var r = document.documentElement;
      r.classList.toggle("dark", d);
      r.style.colorScheme = d ? "dark" : "light";
      r.setAttribute("data-theme", d ? "dark" : "light");
      r.setAttribute("data-theme-pref", pref);
    }
    function pref() {
      var v = localStorage.getItem(K);
      return (v === "light" || v === "dark" || v === "system") ? v : "system";
    }
    apply(pref());
    // 跟随系统时，系统切换要实时生效
    var mq = window.matchMedia("(prefers-color-scheme: dark)");
    if (mq && mq.addEventListener) {
      mq.addEventListener("change", function () { if (pref() === "system") apply("system") });
    }
  } catch (e) {}
})();
```

> ⚠️ 这段脚本必须**同时**设置 `data-theme` 和 `data-theme-pref` ——
> 否则刷新后 CSS 的「当前项打勾」会失效（第一次是客户端组件设的，刷新就没了）。

## 七、⚠️ 另一个实测坑：dev 用 `127.0.0.1` 访问 → React 根本不 hydrate

用 `http://127.0.0.1:3000` 访问 dev server 时，Next 会判定为跨域并**拦截 dev 资源**：

```text
Cross-origin access to Next.js dev resources is blocked by default for safety.

To allow this host in development, add it to "allowedDevOrigins" in next.config.js
```

### 7.1 后果（极具迷惑性）

- 客户端 chunk 被拦 → **React 不 hydrate**
- 页面上所有交互（主题切换按钮、导航里的客户端组件）**全部失效**
- **控制台没有任何报错** —— 只有上面那一行 warning
- 你会以为是 `onClick` 没绑、路径写错、组件没渲染…… 方向完全错

### 7.2 解法

```ts
// next.config.ts
allowedDevOrigins: ["127.0.0.1", "localhost"],
```

本地调试用 `http://localhost:3000`（而不是 `127.0.0.1`）也能绕开。

### 7.3 排查「React 有没有 hydrate」

```js
// 在浏览器控制台执行
Object.keys(document.querySelector('button')).filter(k => k.startsWith('__react'))
// 返回空数组 = 没 hydrate（不是你的组件写错了）
```

这是个通用技巧 —— 以后遇到「组件能渲染但点了没反应」，先用它确认 hydration 到底有没有发生。

## 八、动手实验

### 实验 1：确认报错来源

在项目里临时装回 `next-themes` 并在 `<html>` 上加 `className="light"`：

```bash
pnpm add next-themes
```

```tsx
<html lang="zh-CN" className="light">
```

启动 dev，**不用做任何切换操作**，控制台立刻报：

```text
A tree hydrated but some attributes of the server rendered HTML didn't match
```

**把 `className` 删掉、卸载 next-themes**，回到本课的实现 —— 报错消失。

### 实验 2：亲手触发「图标用 state」的水合报错

把 `ThemeToggle` 改成用 state 控制图标：

```tsx
const [isDark, setIsDark] = useState(false);
useEffect(() => setIsDark(document.documentElement.classList.contains("dark")), []);
return isDark ? <MoonIcon /> : <SunIcon />;
```

**预期**：dev 控制台报 hydration mismatch（服务端 `<Sun>`，客户端首帧 `<Moon>`）。

**改回**双图标 + CSS 切换的写法，报错消失。

> 这就是为什么本课坚持「状态交给 CSS，JS 不参与渲染判断」。

### 实验 3：验证防闪烁

1. 点切换按钮 → 页面变暗
2. F5 刷新
3. **盯住刷新过程**：页面**不应该**先闪一下白色再变暗

**原理**：`<head>` 里的内联脚本在 HTML 解析阶段就把 `dark` 类打好了。

**验证手段**：把 `ThemeScript` 从 `<head>` 移到 `<body>` 末尾，再刷新 —— 闪白出现了。**移回去。**

### 实验 4：验证「跟随系统」实时生效

```js
// 浏览器控制台
localStorage.setItem('theme', 'system');
```

然后把浏览器 DevTools 的模拟配色改成 Dark（Rendering → Emulate CSS `prefers-color-scheme`）：

**预期**：页面**立刻**变暗，无需刷新。

> 靠的是脚本里 `mq.addEventListener("change", ...)` 那一段。

### 实验 5：验证 `suppressHydrationWarning` 的作用范围

把它从 `<html>` 上删掉，点一次切换按钮，然后 F5：

**预期**：控制台报 hydration mismatch（这次是 `class` 与 `style` 不一致）。

**加回来**，报错消失。

> 顺便验证它**不会**掩盖子节点的问题：在 `<main>` 上故意写一个不匹配的 `class`，
> 控制台依然会报 —— 它的作用范围确实只有 `<html>` 自身。

### 实验 6：亲手触发 dev 跨域坑

```bash
pnpm dev
```

```js
// 用 127.0.0.1 访问
location.href = 'http://127.0.0.1:3000/';
```

**预期**：控制台出现 "Cross-origin access to Next.js dev resources is blocked"，
然后**点切换按钮毫无反应**（React 没 hydrate）。

用这一招排查：

```js
Object.keys(document.querySelector('button')).filter(k => k.startsWith('__react'))
// 空数组
```

**解法**：加 `allowedDevOrigins` 或改用 `localhost`。

## 九、常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 图标用 `useState` 控制 | hydration mismatch | 双图标 + CSS `scale/rotate` 切换 |
| 用 `useSyncExternalStore` 存主题 | 同样 mismatch（首帧就返回真实值） | 状态交给 CSS |
| 三态菜单用 `RadioGroup` | mismatch | 普通 item + CSS 画的 ✓ |
| `<html>` 漏 `suppressHydrationWarning` | hydration mismatch | 加上 |
| 用 `next/script` 加载防闪脚本 | 首屏闪一下亮色 | 内联 `<script>` 在 `<head>` |
| CSS 变量写在 `@media (prefers-color-scheme: dark)` 里 | 手动切换无效 | 改成 `.dark { }` 类驱动 |
| 脚本只设 `class` 不设 `data-theme` | 刷新后「当前项打勾」失效 | 两个属性都设 |
| `localStorage` 不 try/catch | 隐私模式下点击静默失败 | 包 try/catch |
| `<Button>` 没加 `relative` | 月亮图标跑到 `<body>` 去了 | `className="relative"` |
| dev 用 `127.0.0.1` 访问 | React 不 hydrate，交互全失效 | 用 `localhost` 或配 `allowedDevOrigins` |

## 十一、小结 & 下一步

- 亮暗模式本质只有三件事：**两套 CSS 变量** + **一个 `.dark` 类** + **一个防闪烁脚本**。
- `next-themes` 不是必需品 —— 它做的事 20 行 DOM 就能做完，且省不掉 hydration 那道坎。
- **hydration mismatch 的三种解法**：服务端也知道（丢静态性）／`suppressHydrationWarning`（只对 `<html>`）／差异发生在 hydration 之后（脚本先行）。
- **状态交给 CSS，JS 不参与渲染判断** —— 这是本课最重要的一条工程原则。
- 排查「组件能渲染但点了没反应」的第一步：确认 React 有没有 hydrate。
