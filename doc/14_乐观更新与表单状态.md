# 第 14 课 · 乐观更新与表单状态

> **学习目标**：掌握 React 19 的 `useOptimistic` 与 `useFormStatus`，写出「点下去立刻有反馈」的表单。
> **对应代码**：`app/(root)/optimistic/page.tsx`、`app/(root)/optimistic/SubmitButton.tsx`、`lib/optimistic-actions.ts`
> **预计耗时**：40 分钟

---

## 一、核心概念

| Hook | 作用 | 约束 |
|---|---|---|
| `useOptimistic` | 服务端结果回来前，先渲染「预计状态」 | 必须在 Action / Transition 内部调用更新函数 |
| `useFormStatus` | 读父级 `<form>` 的 pending 状态 | **必须**写在 form 的子组件里 |

**传统做法**：点提交 → 等接口 → setState → 界面更新（这 1.5s 界面毫无反应）
**乐观做法**：点提交 → 立刻把「预计结果」画出来 → 接口回来后用真实数据替换

---

## 二、真实代码

### 2.1 服务端 action：`lib/optimistic-actions.ts`

```ts
"use server";

export async function addMessage(text: string) {
  await new Promise((resolve) => setTimeout(resolve, 1500));
  return { id: crypto.randomUUID(), text, createdAt: Date.now() };
}
```

故意加了 1.5 秒延迟 —— 这样才能看清乐观更新的效果。

### 2.2 页面：`app/(root)/optimistic/page.tsx`

```tsx
"use client";
import { useOptimistic, useState } from "react";
import { addMessage } from "@/lib/optimistic-actions";
import SubmitButton from "./SubmitButton";

type Message = { id: string; text: string; pending?: boolean };

export default function OptimisticPage() {
  // 真实数据（服务端返回后才进这里）
  const [messages, setMessages] = useState<Message[]>([]);
  // 乐观数据：基于真实数据 + 本次乐观插入
  const [optimisticMessages, addOptimisticMessage] = useOptimistic(
    messages,
    (state: Message[], newMessage: Message) => [...state, newMessage],
  );

  async function handleSubmit(formData: FormData) {
    const text = String(formData.get("text") ?? "").trim();
    if (!text) return;

    // 1) 先乐观插入（UI 立刻响应，pending: true 表示还没落库）
    addOptimisticMessage({ id: "optimistic", text, pending: true });

    // 2) 再发真实请求（Server Action）
    const saved = await addMessage(text);

    // 3) 用真实数据替换掉乐观数据
    setMessages((prev) => [...prev, saved]);
  }

  return (
    <div className="mx-auto max-w-2xl p-6">
      <h1>乐观更新 · useOptimistic + useFormStatus</h1>
      <ul className="mt-6 flex flex-col gap-2">
        {optimisticMessages.map((message, index) => (
          <li
            key={message.id + index}
            className={
              "rounded-md border px-3 py-2 text-sm " +
              (message.pending
                ? "border-amber-300 bg-amber-50 opacity-70 dark:border-amber-700 dark:bg-amber-950"
                : "border-gray-200 dark:border-gray-700")
            }
          >
            {message.text}
            {message.pending ? <span className="ml-2 text-xs">（提交中...）</span> : null}
          </li>
        ))}
      </ul>

      <form action={handleSubmit} className="mt-6 flex gap-2">
        <input
          name="text"
          placeholder="输入内容"
          className="flex-1 rounded-md border border-gray-300 px-3 py-2 text-sm dark:border-gray-700 dark:bg-gray-900"
        />
        <SubmitButton />
      </form>
    </div>
  );
}
```

### 2.3 提交按钮：`app/(root)/optimistic/SubmitButton.tsx`

```tsx
"use client";
import { useFormStatus } from "react-dom";

/**
 * useFormStatus 只能读取【父级 form】的提交状态。
 * 它必须放在 form 组件的【子组件】里 —— 直接写在 form 所在组件中永远拿到 false。
 *
 * React 19 / Next 16 做「提交按钮 loading」的标准写法。
 */
export default function SubmitButton() {
  const { pending } = useFormStatus();

  return (
    <button
      type="submit"
      disabled={pending}
      className="rounded-md bg-blue-600 px-4 py-2 text-sm text-white disabled:opacity-50"
    >
      {pending ? "提交中..." : "提交"}
    </button>
  );
}
```

## 三、两个 Hook 的关键约束

### 3.1 `useOptimistic` 的调用时机

```tsx
const [optimisticMessages, addOptimisticMessage] = useOptimistic(
  messages,                                              // 真实数据
  (state: Message[], newMessage: Message) => [...state, newMessage],  // 合并规则
);
```

- 返回值是 `[乐观值, 添加乐观值的函数]`
- 第二个参数是**合并规则**：拿「当前 state + 新乐观值」算出要显示什么
- **必须在 Action / Transition 内部调用 `addOptimisticMessage`**
  —— 放进 `<form action={...}>` 的处理函数里，React 会自动包成 Transition

### 3.2 `useFormStatus` 必须拆成子组件

```tsx
// ❌ 永远拿到 false
export default function Page() {
  const { pending } = useFormStatus();   // ← form 所在组件，拿不到
  return <form action={action}>...</form>;
}

// ✅ 拆成子组件
export default function SubmitButton() {
  const { pending } = useFormStatus();   // ← form 的子组件
  return <button disabled={pending}>...</button>;
}
```

**原因**：`useFormStatus` 读的是「最近一层祖先 form」的上下文，
form 自己的渲染还没进入那个上下文。

## 四、动手实验

### 实验 1：亲眼看乐观更新

访问 <http://localhost:3000/optimistic>，输入内容点「提交」。

**观察时间线**：

```text
t=0.0s   消息立刻出现，背景淡黄（pending: true），按钮显示「提交中...」
t=1.5s   淡黄消失，按钮恢复，id 变成真实 uuid
```

### 实验 2：验证 useFormStatus 拆组件的必要性

在 `app/(root)/optimistic/page.tsx` 里加 `const { pending } = useFormStatus();`

**预期**：拿不到正确的 pending 值（form 所在组件永远 false）。**删掉**。

### 实验 3：把服务端延迟拉长

把 `lib/optimistic-actions.ts` 里的 `1500` 改成 `5000`，重新提交。

**预期**：乐观效果更明显 —— 消息先出现，然后等 5 秒才变成真实数据。**改回 1500**。

### 实验 4：验证乐观值会被真实值替换

连续提交两次相同内容。

**预期**：两条消息都在，但 id 不同。乐观值只是临时的，最终列表由 `messages` 决定。

## 五、常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 在 form 所在组件里用 `useFormStatus` | 永远 `false` | 拆成子组件 |
| 在 Action 之外调用 `addOptimisticMessage` | 不生效 | 放进 form 的 action 处理函数 |
| 乐观值和真实值用同一个 key | React 复用错节点 | 临时 id 加后缀区分 |
| 忘了 `setMessages` 兜底 | 乐观值永远回不去 | 真实值回来后必须写回真实状态 |

## 七、小结 & 下一步

- `useOptimistic` = 先渲染预计状态，服务端结果到达后自动替换。
- `useFormStatus` = 读父级 form 的 pending，必须拆子组件。
- 两者配合 = 「点下去立刻有反馈」的标准表单形态。
