## 一、⚠️ 实测踩坑清单

这一节每一条都是在本仓库 `next build` + `pnpm start` 下用 `curl` **实测复现**过的，
不是文档抄的。学完前面各课，这里是浓缩版速查。

### 1. PPR 下 `notFound()` 返回 200

| 路由 | 构建产物形态 | HTTP 状态码 | 页面内容 |
|---|---|---|---|
| `/notfound` | `○ Static` | **200 OK** | 404 界面 |
| `/notfound-dynamic` | `◐` PPR 壳子（含 `await connection()`） | **200 OK** | 404 界面 |
| `/ssg/999`（数据不存在） | `◐` PPR 壳子 / ISR | **200 OK** | 404 界面 |
| `/no-such-route`（路由未匹配） | — | **404 Not Found** ✅ | 404 界面 |
| `/api/notfound`（Route Handler） | — | **404 Not Found** ✅ | JSON |

**规则**：响应**已经开始流式输出**（预渲染壳子已随首字节发出）→ 状态码锁定 200。
`await connection()` **救不回来**。要真 404 → Route Handler 显式返回。

### 2. Cache Components 会禁用段级配置

开启 `cacheComponents: true` 后，下面三行**构建期直接报错**：

```tsx
export const dynamic = "force-dynamic";   // ❌
export const revalidate = 5;              // ❌
export const dynamicParams = false;       // ❌
```

报错原文：`Route segment config "dynamic" is not compatible with nextConfig.cacheComponents. Please remove it.`

现代替代：`await connection()` / `"use cache"` + `cacheLife()` / 固定 fallback: blocking。

### 3. 反过来也成立：关掉开关会构建失败

```text
To use "use cache", please enable the feature flag `cacheComponents` in your Next.js config.
```

因为 `app/mycache/CachedPart.tsx` 和 `app/(root)/ssg/[id]/page.tsx` 用了 `"use cache"`。
**本仓库的缓存开关已经不可逆。**

### 4. 不定义 `OPTIONS` → 405，不是自动 204

```bash
curl -i -X OPTIONS http://127.0.0.1:3000/api/books | head -8
```

```text
HTTP/1.1 405 Method Not Allowed
Allow: GET
Allow: HEAD
```

对比手写了 OPTIONS 的 `/api/cors` → `204 No Content` + CORS 头。

### 5. `middleware.ts` 与 `proxy.ts` 不能共存

```text
Both middleware file "./middleware.ts" and proxy file "./proxy.ts" are detected.
Please use "./proxy.ts" only.
```

### 6. `revalidateTag` 是两个参数

```ts
revalidateTag("post-1");           // ❌ TS2554: Expected 2 arguments, but got 1.
revalidateTag("post-1", "max");    // ✅
```

### 7. `params` 是 Promise

```tsx
const { id } = await params;        // ✅
const id = +context.params.id;      // ❌ 静默拿到 NaN
```

### 8. `useSearchParams` 必须包 Suspense

```text
useSearchParams() should be wrapped in a suspense boundary at page "/hooks"
```

### 9. 平行路由的 `default.tsx` 行为

- 硬导航到**没有对应 slot** 的路由 → 渲染该 slot 的 **`default.tsx`**（**不是** not-found）
- 硬导航到**有** slot page 的路由 → 渲染该 slot 的 `page.tsx`
- 软导航 → 保留上一次 slot 的状态

### 10. Zod 4 的 `treeifyError`

```ts
z.treeifyError(result.error).properties   // Zod 4 ✅
result.error.flatten().fieldErrors       // Zod 3 ❌ Zod 4 里编译报错
```

### 11. `error.tsx` 必须接 `error` / `reset`

只写 `return <div>error</div>` 等于没做错误边界 —— 拿不到错误信息，用户也无法重试。

### 12. `global-error.tsx` 必须自带 `<html><body>`

它会**替换根 layout**，不补上就会拿到一个没有 html/body 的文档，**页面全白**。

### 3.3 构建产物标记
