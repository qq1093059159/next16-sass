## 一、next/image

### 1.1 三种图片来源

`app/myimage/page.tsx`：

```tsx
import Image from "next/image";
import profile from "@/public/profile.png";
const len = 2;
export default function MyImage() {
  return (
    <div>
      <h1>Home</h1>
      {/* ① 公共目录字符串路径：必须手写宽高 */}
      <Image src="/profile.png" width={100} height={100} alt="1" />

      {/* ② 静态 import：构建期读图自动注入宽高，无需手写 */}
      <Image src={profile} alt="1" />

      {/* ③ 远程图：必须在 next.config.ts 的 images.remotePatterns 白名单里 */}
      {Array.from({ length: len }).map((_, index) => (
        <Image
          key={index}
          src={`https://eo-img.521799.xyz/i/pc/img${index + 1}.webp`}
          alt="1"
          width={192}
          height={108}
        />
      ))}
    </div>
  );
}
```

| 来源 | 写法 | 宽高 |
|---|---|---|
| ① `public/` 字符串 | `<Image src="/profile.png" width={100} height={100} />` | **必须手写** |
| ② 静态 import | `import profile from "@/public/profile.png"` | **自动注入**（构建期读图） |
| ③ 远程图 | `<Image src="https://..." width={192} height={108} />` | 必须手写 + **必须在 `remotePatterns` 白名单** |

> ⚠️ 静态 import 需要 `tsconfig.json` 配好 `@/public/*` 路径别名（本仓库已配）。

### 1.2 `sizes` 教科书示范

同一个文件里还导出了三个组件：

```tsx
// 头像 - 固定 64px
export function Avatar() {
  return (
    <Image
      src="/avatar.jpg"
      width={64}
      height={64}
      alt="用户头像"
      sizes="64px" // ← 告诉浏览器这张图只需要 64px
    />
  );
}

// 横幅图 - 响应式全宽
export function Banner() {
  return (
    <Image
      src="/banner.jpg"
      width={1920}
      height={600}
      alt="横幅"
      sizes="100vw" // ← 占满整个视口宽度，使用 deviceSizes
    />
  );
}

// 响应式内容图
export function ContentImage() {
  return (
    <Image
      src="/content.jpg"
      width={1200}
      height={800}
      alt="内容图"
      sizes="(max-width: 768px) 100vw, (max-width: 1200px) 50vw, 1200px"
      // ↑ 手机上 100% 宽度，平板上 50%，桌面最大 1200px
    />
  );
}
```

### 1.3 `sizes` 为什么重要

`sizes` 告诉浏览器「这张图在页面上**实际渲染多大**」，
Next 据此从 `deviceSizes` / `imageSizes` 里挑最合适的一档，生成 `srcset`，
让浏览器只下载它真正需要的那一档。

**不写 `sizes` 的后果**：浏览器可能下载最大的一档（比如 3840px），手机上流量白白浪费。

`next.config.ts` 里的档位：

```ts
images: {
  remotePatterns: [
    {
      protocol: 'https', // 协议
      hostname: 'eo-img.521799.xyz', // 主机名
      pathname: '/i/pc/**', // 路径
      port: '', // 端口
    },
  ],
  formats: ['image/avif', 'image/webp'], //默认是 ['image/webp']
  deviceSizes: [640, 750, 828, 1080, 1200, 1920, 2048, 3840], // 设备尺寸
  imageSizes: [16, 32, 48, 64, 96, 128, 256, 384], // 图片尺寸
},
```

- `deviceSizes` —— 用于 `sizes="100vw"` 这类整屏图
- `imageSizes` —— 用于 `sizes="64px"` 这类小图

### 1.4 其它常用 props

| prop | 作用 |
|---|---|
| `fill` | 填满父容器（**必须**给父元素加 `relative` 和尺寸） |
| `priority` | 该图是 LCP 图，**不要懒加载**并提高预加载优先级 |
| `quality` | 压缩质量（默认 75） |
| `placeholder` | `"blur"` 配合 `blurDataURL` 显示模糊占位 |

## 二、next/font

### 2.1 真实代码 `app/(root)/font/page.tsx`

```tsx
import { Inter, Roboto_Mono } from "next/font/google";

/**
 * next/font —— 构建期内置的字体优化。
 *
 * 解决三个问题：
 *  1. 布局偏移（FOUT/CLS）：字体在构建期被 self-host 并计算好尺寸，
 *     浏览器一开页面就知道每个字有多宽，不会出现文字突然跳动。
 *  2. 外部请求：字体文件不打到你自己的服务器，而是由平台 CDN 分发。
 *  3. 隐私：不会把访客的 IP 泄露给 Google Fonts。
 *
 * ⚠️ next/font/google 会在【构建期】去 Google 下载字体并缓存到 .next/cache，
 *    所以首次构建需要网络，之后可以离线构建。
 */

const inter = Inter({
  subsets: ["latin"],
  display: "swap",
  variable: "--font-inter",
});

const mono = Roboto_Mono({
  subsets: ["latin"],
  weight: ["400", "700"],
  display: "swap",
});

export default function FontPage() {
  return (
    <div className={`mx-auto max-w-2xl p-6 ${inter.className}`}>
      <h1>字体优化 · next/font</h1>
      <p className="mt-2 text-sm opacity-70">
        这一段用的是 Inter（variable）。字体文件在构建期被下载、自托管、算好尺寸。
      </p>
      <p className={`mt-4 text-sm ${mono.className}`}>
        这一段用的是 Roboto Mono（指定了 400 / 700 两档字重）。
      </p>
    </div>
  );
}
```

### 2.2 关键选项

| 选项 | 作用 |
|---|---|
| `subsets` | 字符子集（`latin` / `chinese-simplified`…），**必须指定**否则构建报错 |
| `weight` | 字重。变量字体不需要指定；非变量字体必须列出全部用到的字重 |
| `display` | `swap`（默认）/ `optional` / `block` / `fallback` |
| `variable` | 把字体挂到 CSS 变量上（配合 Tailwind v4 的 `@theme` 很好用） |
| `preload` | 是否预加载，默认 `true` |
| `fallback` | 降级字体列表，避免字体切换时跳动 |

### 2.3 两种接入方式

| 方式 | 用法 |
|---|---|
| `next/font/google` | 直接用 Google 字体名，构建期下载并自托管 |
| `next/font/local` | 用自己项目里的字体文件：`src: "./fonts/xxx.woff2"` |

### 2.4 为什么比 `<link href="fonts.googleapis.com">` 好

| 问题 | `<link>` 方式 | `next/font` |
|---|---|---|
| 布局偏移（CLS） | ❌ 字体加载后文字跳动 | ✅ 构建期算好尺寸 |
| 外部请求 | ❌ 访客 IP 泄露给 Google | ✅ 字体自托管 |
| 性能 | ❌ 多一次 DNS + 连接 | ✅ 与页面同源 |
| 缓存 | ❌ | ✅ 强缓存，永久 |

## 三、动手实验

### 实验 1：看 next/image 的产物

访问 <http://localhost:3000/myimage>，DevTools → Network → 过滤 `Img`：

**观察**：图片 URL 形如 `/_next/image?url=...&w=256&q=75`，
`w=` 就是 Next 按 `sizes` 挑的档位，`Content-Type` 是 `image/avif`。

### 实验 2：验证 sizes 的作用

把 `Avatar` 里的 `sizes="64px"` 删掉，重新 build，看 Network 里 `w=` 参数变大了。

**结论**：不写 `sizes`，浏览器会按最大可能的宽度下载。

### 实验 3：验证远程图白名单

把 `next.config.ts` 里 `images.remotePatterns` 的 hostname 改成别的域名，
重新 build，访问 `/myimage`。

**预期**：远程图加载失败（Next 报 "hostname is not configured"）。**改回来**。

### 实验 4：看字体的加载方式

访问 <http://localhost:3000/font>，DevTools → Network：

**观察**：`.woff2` 从**自己的域名**加载（不是 fonts.googleapis.com），
`<head>` 里有 `<link rel="preload" as="font" ...>`。

## 四、常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 远程图不在 `remotePatterns` | 加载失败 | 加白名单 |
| 用 `fill` 但父元素没 `relative` | 图片不显示 | 父容器加 `relative` + 尺寸 |
| 忘了 `alt` | 无障碍问题 + 警告 | 装饰图用 `alt=""` |
| `next/font` 忘了 `subsets` | 构建报错 | 必须指定 |
| 非变量字体没列全 `weight` | 缺字重 | 列全用到的 |
| 大量图片不用 `priority` | LCP 变慢 | 首屏主图加 `priority` |
