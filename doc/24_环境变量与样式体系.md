## 一、环境变量的可见性

### 1.1 真实代码 `app/env/page.tsx`

```tsx
//服务器组件 不要增加`use client`
export default function Env() {
  return (
    <div>
      <h1>Home</h1>
      <p>DB_HOST: {process.env.DB_HOST}</p>
      <p>DB_USER: {process.env.DB_USER}</p>
      <p>DB_PASSWORD: {process.env.DB_PASSWORD}</p>
    </div>
  );
}
```

这是**服务端组件**（没有 `"use client"`），所以能读到 `process.env.*`。

### 1.2 可见性规则

| 变量名 | 服务端组件 | 客户端组件 | 浏览器可见 |
|---|---|---|---|
| `process.env.FOO` | ✅ | ❌ 读到 `undefined` | ❌ |
| `process.env.NEXT_PUBLIC_FOO` | ✅ | ✅ | ✅ **会打进浏览器包** |

> ⚠️ **安全红线**：只有 `NEXT_PUBLIC_` 前缀的变量会被打进浏览器包。
> 密钥类变量（API Key、DB 密码、`AUTH_SECRET`）**绝不能**加这个前缀。

### 1.3 构建期 vs 运行时

`package.json` 里：

```json
"dev": "cross-env DB_HOST=localhost next dev",
"build:prod": "cross-env DB_HOST=8.8.8.8 next build"
```

- `NEXT_PUBLIC_*` 变量在**构建时**被字面量替换 → 改了必须重新 build
- 服务端 `process.env.*` 在**运行时**读取 → 同一个构建产物可以跑在不同环境

**这就是为什么 `pnpm build:prod` 要单独跑一次** —— 它演示的是
「构建期内联 vs 运行时读取」的差别。

### 1.4 `.env` 文件优先级

```text
.env.local              ← 本地覆盖（优先级最高，不应提交）
.env.development.local
.env                    ← 基础配置（可提交，但不能含密钥）
```

## 二、Tailwind v4：CSS-first 配置

**Tailwind v4 没有 `tailwind.config.js`**。全部配置搬进 `app/globals.css`。

### 2.1 核心结构（`app/globals.css` 节选）

```css
@import "tailwindcss";
@import "tw-animate-css";

@custom-variant dark (&:is(.dark *));

/* 定义整体主题样式 */
@theme inline {
  --color-dark-100: #000000;
  --color-dark-200: #0f1117;
  --color-light-900: #ffffff;
  --radius-sm: calc(var(--radius) - 4px);
  --radius-md: calc(var(--radius) - 2px);
  --radius-lg: var(--radius);
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  /* ... 更多 token */
}

/* 定义特定组件样式（只能叫 card） */
@layer components {
  .card {
    @apply p-6 bg-gray-100 border border-gray-300 rounded-lg shadow-lg text-gray-700 text-lg font-semibold leading-relaxed tracking-wide text-center max-w-sm mx-auto mt-10;
  }
}

/* 完全自己定义类名 */
@layer utilities {
  .mycard { @apply p-6 bg-gray-100 border border-gray-300 rounded-lg shadow-lg text-gray-700 text-lg font-semibold leading-relaxed tracking-wide text-center max-w-sm mx-auto mt-10; }
  .background-light900_dark200 { @apply bg-background dark:bg-dark-200; }
  .flex-between { @apply flex justify-between items-center; }
  .text-primary-500 { color: orange; }
}

/* 自定义动画 */
@keyframes background-change {
  0% { background-color: #ff0000; }
  50% { background-color: #00ff00; }
  100% { background-color: #0000ff; }
}
.animated-background { animation: background-change 5s infinite; }
```

### 2.2 v3 → v4 的关键变化

| v3 | v4 |
|---|---|
| `tailwind.config.js` 里配 theme | `@theme` 块里用 CSS 变量 |
| `darkMode: 'class'` | `@custom-variant dark (&:is(.dark *))` |
| `content` 数组声明扫描路径 | **自动扫描**，无需配置 |
| `postcss.config` 引 `tailwindcss` + `autoprefixer` | 只引 `@tailwindcss/postcss` |

> `@custom-variant dark (&:is(.dark *))` 的作用：把 `dark:` 变体改成基于 `.dark` 类，
> 配合 `next-themes` 的 `attribute="class"` 工作。

### 2.3 `@layer` 的三种用法

| layer | 用途 | 例子 |
|---|---|---|
| `@theme` | 定义设计 token（颜色、间距、圆角…） | `--color-dark-100` |
| `@layer components` | 有语义的组件类 | `.card` |
| `@layer utilities` | 纯工具类 | `.flex-between` |

## 三、shadcn/ui 工具链

### 3.1 `components.json` —— shadcn 的配置

```json
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "new-york",
  "rsc": true,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "app/globals.css",
    "baseColor": "neutral",
    "cssVariables": true,
    "prefix": ""
  },
  "iconLibrary": "lucide",
  "aliases": {
    "components": "@/components",
    "utils": "@/lib/utils",
    "ui": "@/components/ui",
    "lib": "@/lib",
    "hooks": "@/hooks"
  },
  "registries": {}
}
```

关键点：

- **`"css": "app/globals.css"`** —— 因为 v4 没有 `tailwind.config.js`，主题写在 CSS 里
- **`"hooks": "@/hooks"`** —— ⚠️ 本仓库**没有** `hooks/` 目录（已记录的缺陷 #10）
- **`"rsc": true`** —— 生成的组件支持服务端渲染

### 3.2 `cn()` —— 所有 shadcn 组件的基石 `lib/utils.ts`

```ts
import { clsx, type ClassValue } from "clsx"
import { twMerge } from "tailwind-merge"

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs))
}
```

两个库各管一件事：

| 库 | 职责 | 例子 |
|---|---|---|
| `clsx` | 拼条件类名 | `clsx("p-2", isActive && "bg-blue")` → `"p-2 bg-blue"` |
| `tailwind-merge` | **消解** Tailwind 类名冲突 | `twMerge("p-2 p-4")` → `"p-4"`（后者胜） |

**为什么需要 merge**：`<Button className="p-8">` 要能覆盖组件内部的 `p-2`，
`tailwind-merge` 保证后写的赢。

### 3.3 shadcn Button 的实现 `components/ui/button.tsx`（节选）

```tsx
import * as React from "react"
import { Slot } from "@radix-ui/react-slot"
import { cva, type VariantProps } from "class-variance-authority"

import { cn } from "@/lib/utils"

const buttonVariants = cva(
  "inline-flex items-center justify-center gap-2 whitespace-nowrap rounded-md text-sm font-medium transition-all disabled:pointer-events-none disabled:opacity-50 ...",
  {
    variants: {
      variant: {
        default: "bg-primary text-primary-foreground hover:bg-primary/90",
        destructive: "bg-destructive text-white hover:bg-destructive/90 ...",
        outline: "border bg-background shadow-xs hover:bg-accent ...",
        secondary: "bg-secondary text-secondary-foreground hover:bg-secondary/80",
        ghost: "hover:bg-accent hover:text-accent-foreground ...",
        link: "text-primary underline-offset-4 hover:underline",
      },
      size: {
        default: "h-9 px-4 py-2 has-[>svg]:px-3",
        sm: "h-8 rounded-md gap-1.5 px-3 has-[>svg]:px-2.5",
        lg: "h-10 rounded-md px-6 has-[>svg]:px-4",
        icon: "size-9",
        "icon-sm": "size-8",
        "icon-lg": "size-10",
      },
    },
    defaultVariants: {
      variant: "default",
      size: "default",
    },
  }
)

function Button({
  className,
  variant = "default",
  size = "default",
  asChild = false,
  ...props
}: React.ComponentProps<"button"> &
  VariantProps<typeof buttonVariants> & {
    asChild?: boolean
  }) {
  const Comp = asChild ? Slot : "button"

  return (
    <Comp
      data-slot="button"
      data-variant={variant}
      data-size={size}
      className={cn(buttonVariants({ variant, size, className }))}
      {...props}
    />
  )
}

export { Button, buttonVariants }
```

**三个值得学的设计**：

1. **`cva`（class-variance-authority）** —— 把「变体 → 类名映射」抽成可复用配置，
   `buttonVariants({ variant, size, className })` 直接产出最终类名。
2. **`asChild` + Radix `Slot`** —— 让 `<Button asChild><Link href="...">按钮</Link></Button>`
   把 Button 的样式套到 Link 上，避免嵌套两个元素。
3. **`cn()` 合并** —— `className` 作为最后一个参数传给 `cva`，`twMerge` 保证它能覆盖默认样式。

### 3.4 暗黑模式链路

```text
context/Theme.tsx           ← 二次封装 next-themes 的 ThemeProvider
components/DarkMode.tsx     ← "use client"，用 useTheme() 切换
app/layout.tsx              ← 引入 <ThemeProvider attribute="class" ...>
app/globals.css             ← @custom-variant dark (&:is(.dark *))
```

`context/Theme.tsx`：

```tsx
"use client";
import { ThemeProvider as NextThemeProvider } from "next-themes";
import { ThemeProviderProps } from "next-themes";
import React from "react";
const ThemeProvider = ({ children, ...props }: ThemeProviderProps) => {
  return <NextThemeProvider {...props}>{children}</NextThemeProvider>;
};
export default ThemeProvider;
```

## 四、动手实验

### 实验 1：环境变量的构建期 vs 运行时

```bash
pnpm dev
curl -s http://127.0.0.1:3000/env | grep -o "DB_HOST: [^<]*"
```

**预期**：`DB_HOST: localhost`（dev 脚本注入的）

```bash
pnpm build:prod && pnpm start
curl -s http://127.0.0.1:3000/env | grep -o "DB_HOST: [^<]*"
```

**预期**：仍然是 `localhost` —— 因为 `pnpm start` 没注入 `DB_HOST`，
而服务端 `process.env` 是**运行时**读取的。

### 实验 2：验证 NEXT_PUBLIC_ 的暴露

在 `.env.local` 加一行 `NEXT_PUBLIC_DEMO="hello"`，然后：

```bash
pnpm build && pnpm start
```

到 `.next/static/chunks/` 里 grep 一下 `hello` —— **能搜到**，
即使页面没直接用它。这就是「会打进浏览器包」的含义。

### 实验 3：验证 Tailwind v4 的自动扫描

在 `app/(root)/about/page.tsx` 里加一个不存在的类：

```tsx
<div className="totally-not-a-real-class">test</div>
```

**预期**：样式不生效，但**不会报错** —— v4 自动扫描源文件，无需声明 `content`。

### 实验 4：验证 twMerge 的冲突消解

给某个 `<Button className="p-8">`，观察最终 padding 是 8 而不是 2。

### 实验 5：验证 dark 变体

在 Navbar 的 className 里加 `bg-red-500 dark:bg-blue-500`，
切换暗黑模式看颜色变化 —— 这条链路是
`@custom-variant dark` + `next-themes`（attribute="class"）+ `.dark` 类共同完成的。

## 五、常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 客户端组件读非 `NEXT_PUBLIC_` 变量 | `undefined` | 密钥放服务端，客户端通过 API 拿 |
| 给密钥加了 `NEXT_PUBLIC_` | **密钥泄漏** | 绝对不行 |
| 改了 `NEXT_PUBLIC_*` 不重新 build | 还是旧值 | 该变量是构建期内联的 |
| v4 里还找 `tailwind.config.js` | 找不到 | 主题写在 `globals.css` 的 `@theme` |
| `cn()` 漏了 `twMerge` | 外部 className 覆盖不了默认样式 | 用本仓库的 `cn` |
| `components.json` 的 `hooks` 指向不存在的目录 | shadcn CLI 报错 | 创建目录或改别名 |

## 七、小结 & 下一步

- 只有 `NEXT_PUBLIC_` 前缀进浏览器包；服务端变量运行时读取。
